# 검증 기록

이 문서는 실행한 검증만 기록한다. 저장 실패 주입과 실제 한글 IME 조합은 아직 별도 확인이 필요하다.

## 빌드와 정적 검사

- 통과: Script Command 다섯 개와 공통 라이브러리에 `bash -n`을 실행했다.
- 통과: 한글·공백·기호 검색어의 UTF-8 percent encoding 결과를 예상값과 비교했다.
- 통과: `Info.plist`의 식별자·URL scheme·실행 파일 이름을 정적으로 확인했다.
- 통과: `CLANG_MODULE_CACHE_PATH="$PWD/.build/module-cache" ./scripts/build-app.sh`로 release 앱 번들을 만들었다.
- 통과: `plutil -lint`와 `codesign --verify --verbose=2`가 `build/Ray Notes.app`에서 통과했다.
- 참고: 제한된 개발 환경에서 SwiftPM manifest sandbox를 끄기 위해 빌드 스크립트는 `--disable-sandbox`를 쓴다. 이는 앱 권한이나 App Sandbox 설정을 바꾸지 않는다.

- 통과: CUA로 작은 창에서 목록이 접힌 상태와 제목 입력 칸 없이 하나의 편집기만 보이는 구성을 확인했다.

- 통과: 목록 확장 시 창 너비가 430에서 660으로 커져 편집기 폭을 유지했고, 다시 접으면 편집기 포커스가 돌아왔다. `⌘F`는 목록을 열고 본문 검색어로 결과를 찾았다.
- 통과: `⌘N` 뒤 즉시 붙여넣은 내용이 `# 메모` 아래 본문에 입력되는 것을 확인했다. 고정 버튼의 접근성 상태가 on/off로 바뀌는 것도 확인했다.
- 통과: 굵게 표시된 텍스트를 추가한 뒤 `⌘Z` 한 번으로 정확히 제거했다. verifier가 JSON과 내보낸 본문이 fixture와 같고 H1이 하나뿐임을 확인했다.
- 통과: `build/ui-markdown-refinement.md`로 내보내기를 확인했다. `⌘Q` 뒤 등록된 Raycast의 최근 노트 명령이 올바른 내용과 접힌 목록 상태로 다시 열었다.
- 통과: 이전 읽기 전용 실행 시점에 기존 legacy 노트 9개의 aggregate가 바뀌지 않은 것을 확인했다. 이후 사용자가 직접 편집한 내용은 이 확인 범위에 포함하지 않는다.

## 제목과 체크리스트 편집

- 통과: H1의 `# ` 접두사가 화면에서 보이지 않으면서 원문에는 남는 것을 확인했다.
- 통과: 일반 목록과 두 칸 들여쓴 목록에서 Return이 각각 `- ` 접두사와 들여쓰기를 유지했다.
- 통과: 일반·중첩 체크리스트의 원형 토글이 `[ ]`와 `[x]` 원문을 바꾸고, `⌘Z`가 원래 상태로 되돌리는 것을 확인했다.
- 통과: 체크리스트 원문 표기가 숨겨지고, 미완료 항목은 윤곽 원, 완료 항목은 채워진 원과 체크로 표시되는 것을 스크린샷으로 확인했다.
- 통과: 완료 체크리스트에서 Return을 누르면 다음 줄에 미완료 체크리스트가 만들어졌다. 빈 `- ` 항목에서 Return을 누르면 표기가 제거됐고, 입력한 줄바꿈은 `⌘Z` 한 번으로 되돌릴 수 있었다.
- 통과: `build/ui-list-checkbox.md` 내보내기를 확인한 뒤 정상 `⌘Q`와 등록된 Raycast 최근 노트 명령으로 다시 열어 체크 상태와 원문 내용이 그대로 복원되는 것을 확인했다.

## 확인 방법

1. `./scripts/build-app.sh`를 실행한다.
2. `plutil -lint "build/Ray Notes.app/Contents/Info.plist"`가 `OK`인지 확인한다.
3. `RAY_NOTES_APP="$PWD/build/Ray Notes.app" ./raycast/commands/new-note.sh`처럼 각 스크립트를 실행해 `open`이 0으로 끝나는지 확인한다.
4. Raycast에서 각 명령을 실행하여 같은 앱 프로세스가 활성화되고 URL 대상 화면이 열리는지 확인한다.

아직 수행하지 않은 항목은 통과로 간주하지 않는다.
